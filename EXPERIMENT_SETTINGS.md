# Experiment settings

Every parameter behind the numbers in the paper, the exact commands that
produced the released result files, and the map from each table and figure of
the paper to the file it is read from. Section numbers refer to the paper.

The reported measurement covers **1,206 pages in 248 kit clusters**. An earlier
measurement of the same study covered 833 pages in 172 clusters; it was
released as v1.0.0 and is kept unchanged in `run1_833/` (Section 13). Every
number in this document belongs to the 1,206-page measurement unless it is
explicitly labelled otherwise.

## 2. Render protocol (Section 4.1)

Identical in `render.py`, `replay_ids.py`, `render_html.py` and `perturb.py`
(`PROTOCOL` dict / module constants):

| setting | value |
|---|---|
| browser | Playwright 1.63.0, bundled Chromium, `--disable-lcd-text --hide-scrollbars` |
| viewport | 1366 × 768, `device_scale_factor` 1 |
| context | `color_scheme=light`, `locale=en-US`, `timezone_id=UTC` |
| navigation | `wait_until=domcontentloaded`, then a fixed 1,200 ms settle; navigation timeout 15,000 ms |
| network | every request except the page's own file is aborted (`ctx.route("**/*", abort)`); no external subresource is ever fetched |
| output | viewport PNG (no full-page capture) |
| serving mode | first pass (`render.py`): loopback HTTP; every later stage (`replay_ids.py`, `render_html.py`, `perturb.py`): `file://`. The switch is documented in `pipeline3.sh`; both classes and every condition take the identical `file://` path in the reported numbers |

Content covariates written per render: `pw_visible` (a password input with
non-zero bounding box), `text_len` (characters of `innerText`), `n_colors`
(colour bins after quantisation to 8 levels per channel that hold at least
0.05 % of the sampled pixels), plus the
fidelity covariates `ink_area` and `block_area` (`fidelity.py`, minimum run
24 px, near-white = every channel ≥ 238).

**Renders of two dates in one gallery.** The 1,206-page gallery re-uses the
834 clean `file://` renders and their perturbed renders made on
22 September 2026 and adds the 372 new pages, whose `file://` renders and
whose perturbed renders in all seven conditions were made on 3 October 2026
(measured from the file timestamps: every directory of the enlarged gallery
holds exactly 834 files dated 22 September 2026 and 372 dated 3 October 2026).
The first-pass renders of all 1,206 pages, including the new ones, date from
22 September 2026 and are part of the 10,520 of the funnel. Nothing in the
toolchain changed between the two dates: Playwright 1.63.0 and its bundled
Chromium were installed on 22 September 2026 and never updated. Determinism
was measured rather than assumed — 60 pages of the first run were re-rendered
in October under the identical protocol and 59 are byte-identical to their
September renders; the single exception differs in 34 of 1,049,088 pixels at
an amplitude of at most 2 grey levels, which is far below every threshold used
in the analysis. Re-using the September renders is therefore equivalent to
re-rendering them.

## 3. Perturbation conditions (Section 4.2, paper Table 2)

Injected at render time as one `<style>` element (`#__p` is an appended
overlay `div`), `perturb.py --cond <c>`; `applied` is `True` when the
rendered pixels differ from the clean render (or the geometry changed).

| cond | injection | applied / 1,206 |
|---|---|---|
| A0n | `#__p{}` (inert style; the null condition) | 39 (re-render noise only) |
| A1 | fixed full-screen overlay, `repeating-linear-gradient(0deg, rgba(0,0,0,.04) 0 1px, transparent 1px 3px)` | 1,206 |
| A3 | `html{filter:invert(1)}` | 1,067 |
| A4 | fixed 370 × 180 px top-left overlay, `repeating-linear-gradient(45deg,#000 0 2px,#fff 2px 4px)` | 1,206 |
| S1 | `img, svg, [class*=logo], [id*=logo], [class*=brand], [id*=brand] {visibility:hidden!important}` | 1,031 |
| S3 | `*{letter-spacing:.3em!important; word-spacing:.35em!important}` | 1,197 |
| S7 | fixed white footer bar, text `© 2024 Aventro Corporation — Aventro Secure Sign-In`, 16 px Arial | 1,206 |

The overlay `z-index` is 2147483647. Inversion left 139 pages unchanged; 129
of them are redeployments of one kit, so the non-applied cells fall in 4 of
the 248 clusters. The paper's Table 4 reports applied-only cells for every
condition except A0n, which is reported over all 248 clusters (the null
condition changes no pixels by design; its applied cell is 39 pages in 19
clusters).

## 4. Representation configurations (Section 4.3, paper Table 3)

Feature extraction: `features.py` (pixel tier through `pixel/`, unmodified
except the fixed-length LBP histogram; CLIP through `open_clip`). Similarity
matrices: `retention2.py` / `retention_excl.py` (`rung_matrices`). Result
keys in the JSON files are given in brackets. Nothing in this section changed
with the enlarged measurement.

| key | configuration | input | feature | similarity |
|---|---|---|---|---|
| `P_color` | colour | full page, HSV (OpenCV 8-bit scale: H 0–180, S/V 0–256) | 8 × 8 × 8 histogram, 512 dims, min-max normalised | Pearson correlation (`HISTCMP_CORREL`), accumulated in float64 |
| `P5_triv8` | 8×8 | RGB, area-averaged 8 × 8 | 192-dim vector | `1 − d / d_max`, `d` Euclidean, `d_max` the largest distance among all query–gallery pairs of the condition |
| `P_ssim_global` | SSIM* | grey, Lanczos 256 × 256 | global μ, σ², σ_qr over all 65,536 pixels | global-statistics SSIM, C1 = (0.01·255)², C2 = (0.03·255)² (paper Eq. 1) |
| `P3_hash` | hash | grey, histogram equalisation, Gaussian blur r = 1, Lanczos | DCT hashes 32 × 32 and 64 × 64 (image resized to 4n × 4n, orthonormal 2-D DCT, top-left n × n block, the 2 × 2 DC corner weighted ×1.5, thresholded at the median of the unweighted block) + Haar LL hashes 32 × 32 and 64 × 64 (image 2n × 2n, one-level Haar, LL thresholded at its median); 10,240 bits | 1 − weighted Hamming fraction, block weights 0.6 (32 × 32) / 0.4 (64 × 64) |
| `P_lbp` | LBP | grey, 128 × 128 | uniform LBP, P = 8, R = 1, fixed 10-bin histogram, L1-normalised | histogram intersection Σ min(h, h′) |
| `P4_hog` | HOG | grey, 128 × 128 | 9 orientations, 8 × 8 px cells, 2 × 2 blocks, L2-Hys, 15 × 15 blocks → 8,100 dims | (cos θ + 1) / 2 |
| `P0_fusion` | fusion | full page + ROI crop | five terms | `0.5·hash + 0.15·colour + 0.10·SSIM* + 0.15·LBP + 0.10·HOG`, each non-SSIM term `0.7·ROI + 0.3·full` (paper Eq. 2); weights in `pixel/config.py` |
| `E1_clip` | CLIP | RGB, short side bicubic to 224, centre crop 224 × 224, CLIP mean/std | `open_clip` `ViT-B-32-quickgelu`, `pretrained="openai"`, 512-dim, L2-normalised | cosine (= dot product) |

ROI (fusion only): Canny edges of the blurred grey image, dilated; contours
with area > 1/1000 of the image filled; a crop of half the image width and
height (at least 30 %) around the densest point of the resulting map; fallback
crop x ∈ [25 %, 75 %], y ∈ [30 %, 80 %] when no contour is found.

Library versions: scikit-image 0.26.0, OpenCV 5.0.0, open_clip_torch 3.3.0,
PyTorch 2.14.0 (CPU), numpy 2.5.3 (`requirements.txt`).

## 5. Primary metric (Section 4.5, paper Table 4)

* Gallery: the 1,206 clean renders (the query's own clean render included; see
  Section 6 below for the exclusion galleries); 345 of them are distinct
  256 × 256 grey thumbnails.
* Hit rule: the query's own kit cluster attains the row maximum of the
  similarity row within `eps = 1e-4` (ties at the maximum are the normal case
  because the gallery contains byte-identical renders).
* Estimand: mean over kit clusters of the per-cluster rank-1 retention
  (`cluster_mean`); page means (`page_mean`) are reported alongside but never
  used in the paper's headline numbers.
* Cells: `applied_only` (cells whose perturbation changed the pixels) for
  A1–S7, which leaves 248 clusters for A1/A4/S7, 246 for S3, 244 for A3 and
  204 for S1; `itt_all` (all 248 clusters) for A0n.
* Uncertainty: cluster bootstrap, B = 4,000, seed 20260922, percentile 2.5 /
  97.5 (`boot95`); `wilson95_full` is the Wilson interval for the fraction of
  fully retained clusters and is not used in the tables.
* Command (as run; `pipeline657.sh` / `pipeline657b.sh` produced the `.npz`
  inputs, `duyarlik.sh` re-ran the analysis at six-decimal rounding):

```bash
./venv/bin/python retention2.py --clean feat_u_A0.npz \
    --conds A0n=feat_u_A0n.npz A1=feat_u_A1.npz A3=feat_u_A3.npz A4=feat_u_A4.npz \
            S1=feat_u_S1.npz S3=feat_u_S3.npz S7=feat_u_S7.npz \
    --clusters clusters_u_flat.json --applied pert_u \
    --out results_retention_u.json
```

`--eps` was left at its default `1e-4`; the released file records `eps`
0.0001. In the released layout the same run is

```bash
./venv/bin/python retention2.py --clean feat_A0.npz \
    --conds A0n=feat_A0n.npz A1=feat_A1.npz A3=feat_A3.npz A4=feat_A4.npz \
            S1=feat_S1.npz S3=feat_S3.npz S7=feat_S7.npz \
    --clusters clusters_flat.json --applied pert --eps 1e-4 \
    --out results_retention_v2.json
```

`retention_excl.py`, run from the `u_run/` link directory of Section 0 so that
its filename defaults resolve to the enlarged inputs; every parameter is a
default, which is why no flag but the paths appears:

```bash
cd u_run

    --clusters clusters_flat.json --applied pert \
    --out ../results_retention_excl_u.json
```

In the released layout, from the repository root, the defaults are already
correct:

```bash
./venv/bin/python retention_excl.py --clean feat_A0.npz \
    --conds A0n A1 A3 A4 S1 S3 S7 --clusters clusters_flat.json \
    --applied pert --eps 1e-4 --out results_retention_excl.json
```

Gallery facts written at the top level of the file: 1,206 pages, 345 distinct
256 × 256 grey thumbnails, 1,029 pages with a byte-identical twin, 168
duplicate groups, none straddling two clusters, 326 distinct-byte pairs
within RMSE ≤ 1 grey level, 228 distinct-byte pairs with identical dHash.

| variant | candidates removed from the query's row |
|---|---|
| `full` | none (reproduces `results_retention_v2.json`) |
| `self_excl` | the query's own clean render |
| `dup_excl` | the own clean render and every clean render whose 256 × 256 grey thumbnail is byte-identical to it |
| `rmse1_excl` | every clean render within RMSE ≤ 1 grey level of the own clean render (sensitivity) |
| `dhash0_excl` | every clean render with the same 256-bit dHash as the own clean render (sensitivity) |

A query whose cluster has no candidate left is dropped; the surviving
population is `n_pages` / `n_clusters` per condition (A3: `full` 1,067 pages /
244 clusters, `self_excl` 957 / 134, `dup_excl` 558 / 39, `rmse1_excl`
512 / 31, `dhash0_excl` 481 / 25). Each variant carries the same population
scored against the full gallery (`rungs_full_gallery_same_population`) and,
for `dup_excl`, also under `self_excl` (`rungs_self_excl_same_population`), so
galleries are compared on one set of clusters. Paired contrasts
(`paired_minus_full`, `paired_hog_minus_clip*`) are the mean over clusters of
the per-cluster difference with the same cluster bootstrap.

The two paired differences quoted in the paper's text on the primary (full)
gallery, HOG − CLIP under A3 and LBP − fusion under A4, come from
`paired_contrasts.py`, run the same way from `u_run/` and released as
`paired_contrasts.py --clean feat_A0.npz --conds A0n A1 A3 A4 S1 S3 S7 --clusters clusters_flat.json --applied pert --eps 1e-4 --out results_paired_contrasts.json`:
per page the rank-1 hit of one configuration minus the hit of the other,
averaged per cluster and then over clusters (`cluster_mean_diff`, applied-only,
same hit rule and bootstrap as Table 4), with the number of clusters whose
mean difference is strictly positive / negative. Each entry also carries a
`*_page_weighted` variant (page mean, cluster-resampled) for traceability to
an earlier audit; the paper quotes the cluster-weighted values only (A3
HOG − CLIP 0.326 [0.269; 0.384], 244 clusters, 81 ahead and 0 behind;
A4 LBP − fusion −0.763 [−0.815; −0.708], 248 clusters, 191 behind and 1
ahead).

## 7. Perceptibility (Section 5.4, paper Table 7, Figure 3)

`perceptibility.py --clean clean_sub_u --pert pert_u --conds A0n A1 A3 A4 S1 S3 S7 --ids ids_u.txt --sample 200 --out results_perceptibility_u.json`

`clean_sub_u/` is the 1,206-render clean gallery and `pert_u/<cond>/` the
perturbed renders; neither is released (Section *What is and is not in this
repository* of `README.md`), and the first run used the same command against
`clean_f/shots` and `pert`.

The 200 pages are a seeded random sample (`numpy.random.default_rng(20260922)`,
`choice` without replacement, inside the script) of the 1,206-id list
`ids_u.txt`. All 200 have both a clean and a perturbed render in every
condition, so every cell has `n = 200`. This sample is **not** the VLM subset
(`ids_vlm200.txt`, the first 200 lines of `ids_u.txt`); the two share 30
pages. Per cell: SSIM (Wang 2004 parameters, Gaussian weights σ = 1.5,
`data_range=255`), mean CIEDE2000, its 99th percentile, and `f_JND` =
fraction of pixels with ΔE2000 > 1.0. The table reports medians over the
200 pages.

## 8. Vision-language model protocol (Section 4.4, paper Table 6)

| setting | value |
|---|---|
| checkpoint | `mlx-community/Qwen3-VL-8B-Instruct-8bit` (affine 8-bit quantisation, group size 64) |
| runtime | `mlx-vlm` 0.7.2, `mlx` 0.32.2, Apple M4 Pro, 64 GB |
| decoding | greedy (temperature 0), `max_tokens` 900 |
| image | longest side resized to 1,024 px (Lanczos) before the processor; one image per chat turn, no history |
| prompt | `vlm/PROMPT.txt`, verbatim (also embedded in `describe.py`) |
| output | one JSON object per render (`brand`, `logo_present`, `page_type`, `asks_for_credentials`, …); the raw text is kept in `raw`, the parsed object in `parsed` (`null` when no JSON object could be extracted) |
| subset | `head -200 ids_u.txt` (sorted id order, no random selection); 97 clusters, 195 pages with a parsable clean answer (93 clusters), largest cluster 29 pages, 158 pages whose clean answer names a brand |
| row counts | 200 rows in every one of the eight conditions; the 199-row irregularity that A1 and S3 had in the first run does not recur |
| legitimate side | `run_benign_vlm.sh`: first 120 of the 156 replayed captures in filename order (120 brand labels, 113 registrable domains); 119 parsed. Unchanged from the first run and carried over as `vlm/desc_BENIGN.jsonl` |
| throughput | median 11.035 s per image (29.2 tokens/s), median prompt 823 tokens, median answer 251 tokens, median peak memory 10.99 GB, over the 1,600 phishing renders described (v1.0.0, 1,598 rows: 11.05 s, 28.5 tokens/s, 823, 246, 10.99 GB) |

The sample was drawn by the same rule as in the first run — the first 200
lines of the measurement set's id list, no random selection — but the list is
now `ids_u.txt`, so the two subsets share only 38 pages. Those 38 pages give
304 cells across the eight conditions, of which 302 exist on both sides (the
first run's A1 and S3 files each lack their last row), and every one of the 302
answers agrees: identical `parsed` object, identical `parse_error`, identical
`raw` (non-null in 6 of the 302, the parse failures, and equal there too), down
to the generation- and prompt-token counts. Once both sides are redacted to the
same standard there is no textual difference left anywhere in the 302: the only
fields that differ at all are `seconds` (298 of the 302 cells) and
`tokens_per_second` (261), which are wall-clock measurements of the two runs and
not model output; `prompt_tokens`, `generation_tokens` and `peak_memory_gb` are
equal in all 302. The two samples therefore differ in composition only, not in
model behaviour.

Retention (`vlm_retention.py`), per page against the page's own clean
answer:

* brand: `re.sub(r"[^a-z0-9]+", "", brand.lower())` on both sides, equal
  after normalisation = retained; denominator = pages whose clean answer names
  a brand (158);
* abstention: clean brand non-null and perturbed brand `null`;
* page type and `asks_for_credentials`: exact equality, denominator = pages
  with a parsable clean answer (195);
* a perturbed answer that cannot be parsed counts as a miss on every channel;
* misattribution (Table 6, `y.atıf` column): the perturbed answer parses and
  names a brand that differs from the clean brand after normalisation,
  including brands invented for pages that were unnamed in the clean run;
  denominator = pages with a parsable clean answer present in the condition
  file (195). `misattribution.py` reproduces the column from
  `vlm/desc_*.jsonl` alone (`results_misattribution.json`: A0n 0/195, A1
  4/195, S3 8/195, A4 9/195, A3 13/195, S7 60/195, S1 6/195) together with
  the named/unnamed split quoted in Section 6.3 (S7: 30 + 30, A3: 7 + 6,
  S1: 6 + 0) and the conditional count on the 158 brand-eligible pages;
* intervals: cluster bootstrap of the page proportion, B = 2,000, seed
  20260922; the table is page-weighted (stated in the paper).

The redaction of transcribed e-mail addresses and URLs in the released
`vlm/desc_*.jsonl` cannot move any of these numbers, and that was measured
rather than argued: replacing **every** e-mail- and URL-shaped string in all
nine description files as the model wrote them, before any redaction (90
e-mail and 14 URL occurrences, matched case-insensitively, the obvious
placeholders included), and re-running `vlm_retention.py`, `misattribution.py`
and `f1_recheck.py` leaves all three result files bit-identical. The scored fields
are `brand`, `page_type` and `asks_for_credentials`; the redaction touches
`visible_text`, `input_fields` and the `raw` text of parse failures.

Commands, as run (`vlm657.sh` for the descriptions, `anlamsal_u.sh` for the
analysis):

```bash

./venv/bin/python describe.py --out vlm_u/desc_<c>.jsonl --images pert_u/<c>/<the 200>.png

./venv/bin/python vlm_retention.py --clean vlm_u/desc_A0.jsonl \
    --conds A0n=vlm_u/desc_A0n.jsonl A1=vlm_u/desc_A1.jsonl A3=vlm_u/desc_A3.jsonl \
```

## 12. Known defects kept for the record

* `P_ssim_global` is accumulated in float32 and cast afterwards; self-SSIM of
  identical renders ranges 0.99954–1.00094, wider than `eps`. Sampled impact:
  no hit flips at `eps ≤ 2e-3` on 120 rows, one flip at `5e-3`.
* `describe.py` writes its 1,024 px input next to the image it reads, as
  `.resized_<id>.png`, and does not delete it; `features.py` collects
  `Path(dir).glob("*.png")`, which in `pathlib` **does** match such
  dotted names. Running the semantic rung before the feature stage on the same
  directory would therefore add 200 spurious gallery rows per directory. It did
  not happen in either released run — the feature caches were built first and
  hold exactly 1,206 rows (833 clean / 834 query rows in the first run, which
  is that run's own documented off-by-one), verified from the `ids` array of
  every `.npz` — but the order matters and `features.py` should skip names
  beginning with a dot.
* `results_pixel_clip.json` was regenerated with the float64 histogram fix;
  its `score_p95` values shifted cosmetically and it is not cited in the
  paper.
* The seven analysis scripts round to 6 decimals in this release
  (`retention2.py`, `retention_excl.py`, `paired_contrasts.py`,
  `perceptibility.py`, `vlm_retention.py`, `misattribution.py`,
  `f1_recheck.py`), because the paper prints three decimals derived from full
  precision and 34 of its table cells could not be printed unambiguously from
  the 4-decimal rounding the first run used (a value whose fourth decimal is
  exactly 5 does not determine its own three-decimal form). The computation,
  the seeds and the bootstrap draws are unchanged;
  only the written precision differs, and the released scripts differ from the
  v1.0.0 ones in nothing but the `round(..., 4)` / `round(..., 3)` calls
  (5, 3, 3, 7, 5, 2 and 10 lines respectively, verified line by line). The
  files in `run1_833/` carry the original 4-decimal values.

Two defects of the first run are **resolved** by this measurement rather than
merely recorded:

* The content gate covered 13 of the 20 shards (a timing accident). It now
  covers all 20; the 657 pages it had missed are in the funnel, and 372 of
  them in the measurement set.
* The last id of `ids_f.txt` was skipped by the shell read loop
  (834 → 833 feature rows). `ids_u.txt` ends with a newline, so all 1,206 ids
  carry a feature vector and every denominator is 1,206; the id that the first
  run skipped (`ff85503356d552ee`, the last line of `ids_u.txt`) is part of
  this measurement.

## 16. Redaction of the model outputs, and how to check it

`vlm/desc_*.jsonl` holds what the model transcribed from the renders, which on
a phishing page can include an address the page itself had pre-filled. In the
eight phishing files every transcribed e-mail address and URL is replaced by
`[email redacted]` / `[url redacted]`. `vlm/desc_BENIGN.jsonl` is not redacted:
what it transcribes is the brands' own public content, it is the same file in
both measurements, and v1.0.0 released it unredacted for that reason.

`vlm_gizlilik_tarama.py` makes the criterion checkable instead of asserted. It
walks every string field of every record, matches e-mail- and URL-shaped
substrings, and classifies each by its domain: a domain reserved by RFC 2606 or
RFC 6761 (`example.com` / `.net` / `.org`, `*.example`, `*.invalid`, `*.test`,
`*.localhost`) cannot correspond to a real mailbox or host and is a placeholder;
anything else needs a human ruling.

```bash
python vlm_gizlilik_tarama.py \
    vlm/desc_A0.jsonl vlm/desc_A0n.jsonl vlm/desc_A1.jsonl \
    vlm/desc_A3.jsonl vlm/desc_A4.jsonl vlm/desc_S1.jsonl \
    vlm/desc_S3.jsonl vlm/desc_S7.jsonl
```

Both patterns are matched case-insensitively, and that is load-bearing
rather than tidy. The model transcribes a page's own capitalisation, and one
page of this sample shows its webmail address in capitals
(`HTTP://WEBMAIL.HINET.NET`); a case-sensitive `https?://` leaves that string in
six of the eight files while still reporting that nothing awaits a ruling. The
string was found by re-scanning case-insensitively and is redacted in the
released files, which is why they carry 11 `[url redacted]` markers and no URL
scheme in any case at all.

**Acceptance condition: no string in the eight phishing files awaits a ruling.**
The released files meet it — the scan reports 58 redaction markers, 32 matches
of 2 distinct strings, and 0 awaiting a ruling, the two survivors being
`name@example.com` and `someone@example.com`. The same condition is met by the
eight files of v1.0.0, which is where it was read from rather than invented
after the fact. `desc_BENIGN.jsonl` is outside the condition by design: the scan
finds 14 matches of 10 distinct strings there, 8 of which it flags for a ruling,

Bare brand hostnames without a scheme (`booking.com`, `chase.com`,
`www.terra.com.br`, `mail.163.com` and the like) are left as they are in both
measurements. They are the brand and webmail-provider names the page displays —
the very content the semantic rung measures — not addresses that identify
anyone, and the published v1.0.0 files keep the same class of string
(`mail.ru`, `fedex.com`, `53.com`).
